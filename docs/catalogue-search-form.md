## Automatic form — Task 21 (2026-11-07)

Local state holds only unfinished text and chip disclosures. Each available suggestion selection, dropdown change, removal and clear-all commits immediately. Ordinary criteria changes and response arrivals keep the same mounted form/input, unfinished text and focus. Removal restores focus to its originating control; clear-all also clears text/disclosures and focuses Public. A reset key changes only for back/forward or explicit invalid-URL correction, clearing transient presentation even when the criteria are equal. Pagination preserves unfinished text. Authored appellations, full accessible names, compact 36px chips/32px removals, single-line ellipsis and keyboard/touch full-label disclosure are unchanged.

`useCatalogueSearch` owns the only page query. Its response publishes result cards/count/headset context and current availability together; stale results are labelled previous, and old disabled flags become selectable provisional hints. Task 20's separate `useCatalogueAvailability` hook has been removed; its seed, cancellation, loading/error and manual-recovery regression coverage is migrated to the unified hook tests. The form does not fetch an extra metadata-only result page per edit.

Tous les mots-clés de titre et les autres critères doivent correspondre. » A loading status announces the automatic search; unresolved initial criteria are not described as selectable.

Invalid URLs remain explicit errors. « Réinitialiser la recherche » intentionally applies safe defaults and automatically loads the unfiltered catalogue, preserving unrelated URL parameters/hash. The explanation makes that reset clear, and Public receives focus once trusted controls become ready. No reset occurs merely by loading an invalid URL.

## Parent contract and state

`CatalogueSearchForm` takes `applied`, validated `references` for audiences/headsets, `onSubmit`, optional `disabled` and optional `resetKey`. It renders inside the existing QueryClientProvider, as required by KeywordSelector. SearchFormCriteria derives from the existing browser request contract: selected typed job/title suggestions plus optional audience/headset/legacyQuery. No second dictionary or search predicate is introduced.

The form copies applied criteria into local pending state and owns unselected keyword text. Dropdown edits, keyword selection, removals and clear-all emit no submission. Only Rechercher calls onSubmit with the complete pending criteria, retaining authored selected appellations, source keys and legacy q. The parent remains responsible for accepting those criteria as applied and translating/validating URL data; the form does not navigate, fetch results, reset pagination, alter card headset displays or touch the session draft.

A new semantic applied selection remounts the pending form, clearing unsubmitted text/errors/disclosures. `resetKey` lets the future owner do the same for each applied history/page-navigation event even if criteria are semantically equal. Merely recreating the applied object does not discard pending edits. Task 17B must provide a changing navigation token where needed.

The modified cue appears only when pending selections differ from applied selections; raw unselected input alone is not a criterion. Comparison ignores keyword order but retains selected job source identity and the exact legacy substring. Duplicate job aliases preserve the first chosen source; duplicate title identities do not add criteria. A job and title with similar text remain separate. The ten-slot bound includes legacy q, alongside the selector/server bounds.

Rechercher with nonempty unselected text focuses the keyword input and shows the agreed explanation. No free-text chip is created. Empty criteria are a valid submission. Clear-all removes public/headset, keywords, legacy q and typed text without submitting; focus returns to Public, or the keyword input if that select is unavailable. Clear-all is also available when there is only unselected text. Native dropdown values are captured before queued React state updates.

## Responsive controls

DOM and keyboard order is Public → Métiers ou mots-clés → Casque VR → Rechercher. Public/headset remain native selects. Following candidate browser feedback on 2026-11-07, these four search controls use the standard action-button height (44px / min-h-11) and text-sm (14px), matching Ajouter à ma séance and Finaliser ma séance. This overrides only the keyword input’s shared Input defaults and removes the form’s former 48px minimums; other input primitives and suggestion-option targets are unchanged. Default Tous les publics means no audience, while the supplied Tout public ID remains a separate exact value. Matching Heroicons outline accompany labels and chips: UserGroup, Briefcase, MagnifyingGlass and Eye.

The form establishes a named inline-size container. Below 32rem of allocated width, controls stack and Rechercher spans the full width. From 32rem, Public and keywords each occupy a full row, followed by headset and submit together. From the existing 80rem desktop/draft-rail viewport breakpoint, an allocated form width of at least 45rem (adjusted in Task 17B after checking the actual draft-rail allocation) allows one row with twice the column capacity for keywords. A constrained desktop container retains the stacked/tablet composition. Scoped named CSS classes define this grid; no global layout or draft-panel change is made.

## Shared chip area

`SearchCriteriaChips` renders one full-width list beneath the controls, in public → jobs → title keywords → legacy title condition → headset order. Category text is replaced visually by its icon; complete category/value names remain in accessible reveal/removal names. Default dropdowns do not create chips. Clear-all and « Tous les critères sélectionnés doivent correspondre. » follow the shared area.

Each whole chip can wrap onto another row. Within the chip, only the text is single-line and ellipsized; its icon and 32px remove button do not shrink or disappear. Candidate feedback on 2026-11-07 reduced the whole chip to 36px with tighter internal padding, between the video-card headset badge and the 44px search controls; label text remains text-sm. The chip cannot exceed its available container width. The list/chip surfaces do not clip focus rings to hide overflow. Complete labels remain in state, callback values and accessible names.

The text/icon part is a disclosure button. Clicking/tapping or pressing Enter reveals a separate full-width inline region containing the complete, wrapping label and its category. Closing the region or pressing Escape restores focus to the same disclosure trigger. This provides full-label access without a hover-only title or another overlay. The legacy q disclosure also explains historical contiguous-substring semantics. Removing a chip closes the disclosure and focuses its originating dropdown or the keyword input. Removing a dropdown chip changes its pending value to the default; it does not search immediately.

Composing the selector exposed a stale “added” announcement after clear-all. A failing-first form test reproduced it; the selector now shows that announcement only while its corresponding item is still selected, restoring normal help after removal/reset.
